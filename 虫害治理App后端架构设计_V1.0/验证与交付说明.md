# 后端架构设计交付说明

采用 Java 模块化单体＋独立 Worker＋MySQL＋私有对象存储。Java 与 MySQL 为用户指定；Temurin 21、Spring Boot 4.1.2、MySQL 8.4 LTS 及部署容量为设计建议，需在开发环境落实版本锁定。

## 阅读顺序

1. 《虫害治理App后端架构设计_V1.0.docx》或同名 PDF：16 页，包含总体架构、模块、事务、离线同步、双签与报告版本、安全、部署及验收。
2. 《实现补充约定.md》：内部到 API 状态映射、文本列宽对齐、签字替换与发布重试、风险与投影规则。
3. 《接口到模块和数据表映射.md》：54 项既有员工端 operationId 的模块与表归属。
4. 《MySQL完整数据字典.md》与 `schema-model.json`：44 张表、464 个字段、96 条外键。
5. `V001__initial_schema.sql`：空 schema 的初始建表迁移。`关键事务与查询.sql` 是带 Java 绑定参数的设计示例，不是可整份执行的迁移。
6. `图表/`：3 张 PNG 及对应 Mermaid 源文件，可独立阅读和维护。
7. 《领域术语与架构决策.md》：业务词汇与三个 Proposed 状态的架构决策。

既有白模、需求和 OpenAPI 保持原文件不变；本包不重复携带这些大文件。来源摘要记录在《来源与版本清单.json》。

## 数据库使用方式

为开发环境准备空的 MySQL 8.4 schema，通过迁移账号运行 V001。脚本不创建数据库或账号、不包含默认密码、不包含 DROP。已有数据的环境需要另写增量迁移，不能重跑 V001。日后 Flyway 按新版本新增迁移，不能改写已执行版本。

DDL 为业务设计的物理模型，不包含 Java 权限、完整性校验、文件校验和队列执行代码。开发前将接口文本上限与列宽对齐；超过限制返回结构化 422，禁止截断。
